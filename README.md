# VibeTrack — студия ню-метала

Загружаешь трек → получаешь его ню-метал версию: с нужными инструментами,
мужским и/или женским вокалом, разделением на дорожки, текстом с аккордами,
табулатурами и возможностью записать свой голос прямо в браузере с
автоматической обработкой.

```
исходный трек ──► анализ ──► разделение на дорожки ──► расшифровка текста
                    │              │                        │
                    ▼              ▼                        ▼
                 темп/тональность/сетка долей/аккорды/секции
                    │
                    ▼
        описание словами ──► ArrangementSpec ──► секвенсор ──► синтез инструментов
        («в духе Korn,         (строй, грув,      (рифы,          (гитары, бас,
          drop A, скретчи,      инструменты,       барабаны,       барабаны,
          женский припев»)      вокал)             бас, скретчи)   скретчи, пэды)
                                                        │
                    ┌───────────────────────────────────┤
                    ▼                                   ▼
             табы и аккорды                    сведение + мастеринг
                    │                                   │
                    ▼                                   ▼
        текст с аккордами, ASCII-табы          мастер + дорожки (stems)
                                                        │
                                     запись голоса ─────┘
                                     (авто-обработка, компенсация задержки)
```

## Почему Django, а не FastAPI

Задача не «быстрый JSON-эндпоинт», а долгие тяжёлые джобы с состоянием:
загрузки файлов, очередь рендеров, пользователи, биллинг по кредитам,
админка для разбора упавших задач. Всё это Django даёт из коробки
(ORM + миграции + admin + FileField/Storage + права), а тяжёлую работу
всё равно уносит Celery — то есть выигрыш FastAPI в асинхронности здесь
не работает: рендер упирается в CPU, а не в ожидание I/O.

Практически: `POST /api/tracks/{id}/transform/` только кладёт задачу в
очередь и отвечает за миллисекунды; всё остальное делает воркер.
Если позже понадобится realtime (стриминг прогресса, совместная работа
над проектом) — под это уже подключён ASGI, и добавляется Channels,
без переписывания сервиса.

## Что умеет

| Возможность | Как сделано |
|---|---|
| Анализ трека | темп, сетка долей, тональность, хрома, секции (`engine/analysis.py`) |
| Аккорды | шаблоны + приоритет тональности + динамическое программирование по последовательности (`engine/chords.py`) |
| Стили | 8 жанров как пресеты грува, строя, инструментов и подачи вокала (`GENRES`) |
| Разделение на дорожки | Demucs, если установлен; иначе DSP-разделение (центр-канал + HPSS) (`engine/separation.py`) |
| Понимание описания | правило-ориентированный парсер RU/EN + опционально LLM (`engine/arrangement.py`) |
| Аранжировка | грув-паттерны, power-chords в drop-строях, партии баса/барабанов/перкуссии/скретчей (`engine/sequencer.py`) |
| Звук инструментов | модель струны Карплуса-Стронга, двухкаскадный усилитель, свёртка с импульсом кабинета (`engine/instruments.py`) |
| Смена тональности | сдвиг аккордов, ладов в табах и вокала за ними (`transpose`, −12..+12 полутонов) |
| Текст песни | Whisper (если установлен) либо ручной текст, разложенный по секциям (`engine/transcription.py`) |
| Табы и аккорды | ASCII-табы ровно тех нот, что звучат в миксе (`engine/tabs.py`) |
| Вокал | цепочка обработки под стиль, автотюн, дабл, гармонии, смена пола голоса (`engine/vocals.py`) |
| Запись голоса | MediaRecorder в браузере → компенсация задержки → обработка → микс |
| Сведение | частотная развязка шин, сайдчейн, шинная компрессия, лимитер (`engine/mixing.py`) |
| Личный кабинет | регистрация, история треков, тарифы, списания и возвраты (`core/billing.py`) |

Движок (`engine/`) не знает про Django: на вход пути к файлам, на выход —
данные. Поэтому его можно тестировать без БД и использовать из CLI.

## Нейросети

Базовая установка (numpy + scipy + soundfile) даёт полный цикл без единой
модели. Нейросети — слой поверх, который включается сам, как только пакеты
установлены, и повышает качество:

| Пакет | Что улучшает | Что будет без него |
|---|---|---|
| `demucs` + `torch` | студийное разделение исходника на дорожки | DSP-разделение (хуже, но работает) |
| `faster-whisper` | расшифровка текста с таймкодами по словам | текст вводится вручную, аккорды подставляются автоматически |
| `anthropic` | разбор произвольных описаний аранжировки | детерминированный парсер ключевых слов |
| `ffmpeg` | mp3/m4a/webm на вход и выход | только wav/flac/ogg |

```bash
pip install -r requirements-ml.txt     # или docker build --build-arg WITH_ML=1 .
python manage.py models                # что доступно прямо сейчас
python manage.py models --preload      # скачать веса и прогреть (до приёма трафика)
```

**Модели грузятся один раз на процесс** (`engine/models.py`): воркер Celery
живёт долго, а инициализация Demucs занимает десятки секунд — держать её в
задаче значило бы платить этим временем на каждом рендере. Загрузка защищена
блокировкой, так что параллельные задачи не соберут модель дважды. В
docker-compose веса лежат в отдельном томе `models` и переживают перезапуск
контейнера, а `VIBETRACK_PRELOAD_MODELS=1` греет их при старте воркера.

**Любой сбой модели — не ошибка рендера.** Нет весов, нет сети, упал
инференс — сервис пишет предупреждение в результат и доделывает работу
DSP-методом. Это проверено не только моком: в песочнице, где скачивание
весов заблокировано, конвейер честно откатился и отдал дорожки.

Выбор бэкенда разделения: `VIBETRACK_SEPARATION_BACKEND=auto|demucs|dsp`
(например, `dsp` для бесплатного тарифа и `demucs` для платного).

### LLM для описания аранжировки

`engine/llm.py` превращает свободный текст в параметры аранжировки через
structured outputs — модель выбирает только из допустимых значений, а не
придумывает свои. Справочник инструментов и строёв кэшируется в промпте,
поэтому вызов стоит примерно 0,2–1 ₽ за рендер в зависимости от модели.

Приоритет жёсткий: **правила → LLM → переключатели в форме.** Что
пользователь выставил руками, не переопределит никакая модель — это
покрыто тестом `test_user_overrides_beat_the_model`.

```bash
export ANTHROPIC_API_KEY=...
export VIBETRACK_LLM_MODEL=claude-opus-5   # дешевле: claude-sonnet-5, claude-haiku-4-5
```

### Сколько это стоит по времени

Замерено на 4 vCPU Xeon 2.8 ГГц, трек 2:51:

| Конфигурация | Время рендера | Источник цифры |
|---|---|---|
| Без нейросетей (DSP-разделение) | 88 с | замер |
| Demucs + Whisper на CPU | ~5,5 мин | оценка |
| Demucs + Whisper на GPU | ~1,7 мин | оценка |

Оценки не проверены на этом железе: домены с весами моделей закрыты в
песочнице разработки. Первое, что стоит сделать после `--preload` в рабочем
окружении, — замерить реальные числа: они пишутся в лог и в
`result["timings"]` каждого рендера.

## Требования к серверу

Замерено на 4 vCPU Xeon 2.8 ГГц, трек 2:51:

| Ресурс | Сколько нужно | Замер |
|---|---|---|
| Память на один рендер | **2,1 ГБ** пик | измерено (без Demucs) |
| Память с Demucs на CPU | ~5 ГБ пик | оценка |
| Время рендера трека 2:51 | 88–110 с | измерено |
| Диск: окружение с моделями | ~3,5 ГБ | CPU-сборка torch (2,5 ГБ) + веса (1 ГБ) |
| Диск: один рендер | 379 МБ в WAV, ~40 МБ в mp3 | измерено |

Отсюда рабочая конфигурация: **4 ядра, 6 ГБ памяти, 80 ГБ NVMe,
`--concurrency=1`** и 4 ГБ swap как страховка от OOM на пике Demucs. Два
параллельных рендера потребуют вдвое больше памяти, а ядра при небольшом
потоке всё равно простаивают — параллелить нечего.

На CPU-машине ставьте CPU-сборку torch (см. `requirements-ml.txt`): обычный
пакет с PyPI тянет 3,2 ГБ библиотек CUDA, которые без видеокарты просто
занимают диск.

Пик памяти держат полноразмерные дорожки в памяти микса. Полноценно его
опустить может только потоковая обработка кусками — пока вместо этого убраны
самые дорогие транзиенты: покадровый сдвиг формант вместо БПФ на весь трек
(−1,3 ГБ), overlap-add в ревербераторе, блочный фазовый вокодер во float32 и
освобождение дорожек по мере сведения.

Хранение — отдельная статья: 500 рендеров в месяц в WAV это 190 ГБ архива,
в mp3 — 20 ГБ. Стемы стоит отдавать в mp3, а WAV оставить платному тарифу.

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build          # web на http://localhost:8000
```

Без Docker:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
# в отдельном терминале (нужен Redis):
celery -A vibetrack_site worker --loglevel=info
# либо без Redis, синхронно:  CELERY_TASK_ALWAYS_EAGER=1 python manage.py runserver
```

Открой `http://localhost:8000` — это студия: загрузка трека, описание
аранжировки, прогресс рендера, плееры дорожек, партитура и запись голоса.

## Почему аккордов стало меньше

Наивный подход «взять лучший шаблон на каждом такте» даёт вдвое больше
аккордов, чем слышит человек: на реальном треке было 86, стало 18. Работают
три вещи вместе:

* **простой словарь** — мажор и минор. Септаккорд формально ближе к хроме, но
  в песеннике и на сайтах с аккордами напишут трезвучие;
* **приоритет тональности** — не только «свой ли это тон», но и «то ли
  наклонение». Терцию в плотном миксе почти не слышно, и подсказка гаммы
  чинит большинство ошибок вида Gm вместо G;
* **динамическое программирование** — выбирается лучшая последовательность
  целиком, а не лучший аккорд по отдельности, поэтому один дрогнувший такт
  не рождает лишний аккорд. Штраф за смену подобран так, чтобы честная
  смена каждый такт сохранялась (проверено тестом).

## Тарифы и лимиты

| Тариф | Цена | Треков | Что даёт |
|---|---|---|---|
| Проба | 0 ₽ | 2 | mp3, DSP-разделение |
| Разовый трек | 190 ₽ | 1 | всё, WAV-дорожки, коммерческая лицензия |
| Старт | 390 ₽/мес | 40 | mp3-дорожки, Demucs |
| Студия | 690 ₽/мес | 90 | WAV, приоритет, коммерческая лицензия |
| Продакшн | 1 690 ₽/мес | 200 | всё, бессрочное хранение |

Тарифы описаны в `core/billing.py` — это обычный словарь, менять цены можно
без миграций. Тариф решает не только лимит, но и качество: бесплатная проба
идёт через DSP-разделение и mp3, платные — через Demucs и WAV.

Два правила учёта, которые стоит знать:

* **Списание происходит при постановке в очередь**, а не по факту готовности —
  иначе можно наплодить задач быстрее, чем они считаются.
* **Упавший рендер возвращает списание автоматически.** Сгоревший трек за
  нашу же ошибку — самая обидная причина, по которой люди не возвращаются.

Оплата: `POST /api/billing/checkout/` создаёт счёт в статусе «ожидает».
Подтверждение — вручную в админке (действие «Отметить оплаченным») или
`VIBETRACK_PAYMENTS_TEST_MODE=1` для проверки всего цикла. Подключение
ЮKassa или другого провайдера — это реализация `checkout` и вебхука
подтверждения; специально не сделано «на автомате», чтобы нельзя было
выдать себе подписку, просто дёрнув эндпоинт.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/capabilities/` | инструменты, строи, грувы, доступные бэкенды |
| `POST` | `/api/parse-description/` | как система поняла описание (предпросмотр) |
| `POST` | `/api/tracks/upload/` | загрузка исходника (multipart: `file`, `title`) |
| `POST` | `/api/tracks/{id}/transform/` | запуск рендера, отвечает `202` с id задачи |
| `GET` | `/api/renders/{id}/status/` | статус, стадия, прогресс |
| `GET` | `/api/renders/{id}/` | результат: мастер, дорожки, партитура |
| `GET` | `/api/renders/{id}/score/` | текст с аккордами, аккорды, табы |
| `GET` | `/api/renders/{id}/download/{master\|имя_дорожки}/` | скачивание |
| `POST` | `/api/vocal-takes/` | загрузка записанного голоса (multipart) |
| `POST` | `/api/vocal-takes/{id}/reprocess/` | перепрогнать дубль с другими настройками |
| `GET` | `/api/billing/summary/` | тариф, остаток треков, витрина тарифов |
| `POST` | `/api/billing/checkout/` | счёт на выбранный тариф |
| `GET` | `/cabinet/` | личный кабинет: треки, тариф, платежи |

Пример запуска рендера:

```bash
curl -X POST http://localhost:8000/api/tracks/1/transform/ \
  -H 'Content-Type: application/json' -d '{
    "prompt": "ню-метал в духе Korn, семиструнка drop A, пятиструнный бас, скретчи и бонго, мужская читка в куплете и женский чистый вокал в припеве, 95 bpm",
    "overrides": {"aggression": 0.9},
    "options": {"manual_lyrics": "Я иду сквозь этот шум"}
  }'
```

`prompt` понимает: референсы (Korn, Slipknot, Limp Bizkit, Linkin Park,
Deftones, System of a Down…), строй (drop A/B/C/D, 7- и 8-струнные),
инструменты (скретчи, бонго, пэды, соло-гитара), грув, темп в BPM,
пол и стиль вокала. `overrides` из формы всегда важнее текста.

## Тесты

```bash
python manage.py test           # 54 теста: движок, слой нейросетей и API
```

Тесты движка (`tests/test_engine.py`) проверяют реальные величины:
определение темпа и тональности, распознавание последовательности Am–F–C–G,
одинаковый лад power-chord в drop-строе, отсутствие клиппинга в мастере,
компенсацию задержки записи с точностью до нескольких миллисекунд.
Тесты API (`core/tests.py`) прогоняют полный цикл: загрузка → рендер →
дорожки → партитура → запись голоса. Тесты слоя нейросетей
(`tests/test_ml.py`) работают на заглушках вместо весов и проверяют то, что
ломается в проде: что модель собирается один раз, что падение Demucs
откатывается в DSP, что Whisper зовётся с `condition_on_previous_text=False`
(иначе он зацикливается на повторяющихся припевах) и что ручные настройки
главнее ответа LLM.

## Что дальше

1. **Живые сэмплы барабанов вместо синтеза** — самое слышимое, что осталось.
   Гитара уже считается моделью струны и свёрткой с импульсом кабинета
   (свой импульс подставляется через `VIBETRACK_CAB_IR`), а барабаны всё ещё
   синтезируются. Слот `engine/instruments.SampleKit` под это готов.
2. **Генеративная модель вместо синтеза.** Провайдерский слой
   (`engine/rendering.py`) готов к тому, чтобы рядом встал
   MusicGen/Stable Audio и рендерил партии по тому же `ArrangementSpec` —
   табы и сетка при этом останутся от секвенсора.
3. **Выравнивание вокала по сетке** (WSOLA по слогам) — сейчас
   компенсируется только общая задержка записи.
4. **Экспорт MIDI и Guitar Pro** — данные для этого уже есть в
   `Arrangement.parts`.
5. **Хранилище S3** (`django-storages`) вместо локальной медиапапки при росте нагрузки.

## Заметки по репозиторию

* `db.sqlite3` и файлы в `audio/` лежат в git с ранних коммитов; для рабочего
  окружения их стоит удалить из индекса (`git rm --cached`), новые артефакты
  уже игнорируются через `.gitignore`.
* Медиафайлы пишутся в `MEDIA_ROOT` (`media/` по умолчанию): `renders/job_<id>/`
  — мастер, дорожки и партитура, `takes/take_<id>/` — вокальные дубли.
